# Память проекта

## О проекте
<!-- Краткое описание: что делает проект, для кого, основная ценность -->
**ember** — Python-библиотека для простой интеграции с LLM-провайдерами и создания собственных агентов. Предоставляет единый простой интерфейс для работы с языковыми моделями и создания агентов. Проект на ранней стадии (v0.1.0), API активно меняется.

## Архитектура
<!-- Ключевые компоненты, структура директорий, основные модули -->
- `ember/` — основной пакет (пока только `__init__.py` с `__version__`)
- `tests/` — тесты (pytest), сейчас smoke-тест
- `pyproject.toml` — управление зависимостями через Poetry 2.x
- `.github/workflows/ci.yml` — CI: lint (ruff), typecheck (mypy), test (pytest) на Python 3.10–3.12

## Соглашения
<!-- Code style, нейминг, подходы к тестированию, Git-стратегия -->
- Линтер/форматтер: **ruff** (line-length 100, правила E,F,W,I,UP,B,SIM)
- Типизация: **mypy** в strict-режиме
- Тесты: **pytest** в `tests/`, минимальный добавлен
- Git: ветки вида `setup/...`, `feat/...`; коммиты в стиле Conventional Commits
- Пакет устанавливается editable: `pip install -e .`

## Известные грабли
<!-- Места, где легко ошибиться; устаревшие подходы; скрытые зависимости -->
- **poetry.lock ещё не сгенерирован** — команда `poetry` недоступна в песочнице ассистента; создастся при первом `poetry install` (локально или в CI)
- В песочнице недоступны: `poetry`, `ruff` (не входит в белый список команд); доступны: `pip`, `pytest`, `mypy` (mypy не установлен глобально)
- `poetry.lock` в `.gitignore` закомментирован — файл lock будет трекаться (рекомендация Poetry)

## Стек и команды
<!-- Основные технологии, как запускать, тестировать, деплоить -->
- Python 3.12 (поддержка в CI: 3.10–3.12), Poetry 2.4.2
- Установка: `poetry install` (или `pip install -e .`)
- Тесты: `pytest -q` / `poetry run pytest`
- Линт: `poetry run ruff check .`, формат: `poetry run ruff format --check .`
- Типы: `poetry run mypy ember`
